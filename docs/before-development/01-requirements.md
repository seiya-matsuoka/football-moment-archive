# Football Moment Archive 要件定義

## 1. 文書概要

### 1.1 目的

本書は、`football-moment-archive` の開発開始前に確定した要件を整理し、実装範囲と完成条件を明確にするための文書である。  
本書は開発中の判断基準として使用する。  
実装完了後は、完成した仕様と実装内容を反映した設計書を別途作成する。

### 1.2 対象リポジトリ

- リポジトリ名：`football-moment-archive`
- アプリ名：Football Moment Archive
- アプリ種別：個人開発・学習用 Web アプリ

## 2. アプリ概要

Football Moment Archive は、サッカーの試合で記憶に残った場面を登録・閲覧する Web アプリである。  
試合結果や詳細なスタッツを網羅的に記録することではなく、次の内容を残すことを主目的とする。

- どの試合で起きた場面か
- どのような種類の場面か
- 誰または何が中心となった場面か
- どのような内容だったか
- なぜ印象に残ったか

アプリの中心となる情報は「場面」とし、「試合」は場面が発生した背景情報として扱う。

## 3. 開発目的

本開発では、Next.js の App Router を使用した小規模なフルスタック Web アプリを完成させ、主要機能を一通り実装することを目的とする。  
主な学習対象は次のとおりである。

- App Router によるルーティング
- Server Component によるデータ取得
- Server Action によるデータ更新
- Client Component の必要最小限の利用
- PostgreSQL との接続
- Data Access Layer を介した SQL 実行
- 動的ルート
- URL 検索パラメーター
- 検索・絞り込み・並び替え・ページネーション
- 入力値検証
- `loading.tsx`、`error.tsx`、`not-found.tsx`
- Metadata API
- Vercel へのデプロイ

機能や周辺技術を増やしすぎず、短期間で完成できる規模を維持する。

## 4. 対象範囲

### 4.1 対象リーグ・シーズン

- リーグ：イングランド・プレミアリーグ
- シーズン：2025/26 シーズン
- 対象試合：プレミアリーグのリーグ戦のみ
- 対象チーム：2025/26 シーズンにプレミアリーグへ所属した 20 チーム

対象チームは固定された選択肢として扱い、利用者による追加・編集・削除は行わない。

### 4.2 対象外の大会・試合

次の大会・試合は対象外とする。

- FA カップ
- EFL カップ
- UEFA チャンピオンズリーグ
- UEFA ヨーロッパリーグ
- UEFA カンファレンスリーグ
- コミュニティ・シールド
- 親善試合
- 下位カテゴリーの試合
- 2025/26 シーズン以外の試合
- 他国リーグの試合

### 4.3 公式データとの照合

公式試合データや外部サッカー API は使用しない。試合と場面は利用者が手動で登録する。  
次の照合は行わない。

- 入力された 2 チームが実際に対戦したか
- 試合日が公式日程と一致するか
- ホームとアウェーが公式日程と一致するか
- スコアが公式結果と一致するか
- 同じ試合がすでに登録されているか

## 5. 利用形態

### 5.1 公開範囲

認証を設けない公開デモとして提供する。

- 誰でも閲覧可能
- 誰でも登録可能
- 誰でも編集可能
- 誰でも削除可能
- すべての利用者が同じデータを共有
- 利用者ごとのデータ分離なし

### 5.2 データ保護方針

公開デモであるため、登録データの永続的な保持は保証しない。

- 他の利用者による編集・削除を許容
- 荒らしによるデータ変更・削除を許容
- 必要に応じてシードデータを再投入
- 復旧が難しい場合はアプリの公開を停止

画面上には、共有データであることと個人情報を入力しないことを案内する。

## 6. 用語

### 6.1 試合

場面が発生したサッカーの試合を表す。ホームチーム、アウェーチーム、試合日、スコアを保持する。

### 6.2 場面

試合の中で記録しておきたい出来事を表す。日本語の UI とドキュメントでは「場面」、プログラム上では `Moment`、`moment`、`moments` を使用する。

### 6.3 場面の種類

場面がどのような出来事であるかを分類する固定項目である。

- ゴール
- セーブ
- パス
- ドリブル
- 守備
- 戦術・交代
- 判定
- 反応・雰囲気
- その他

### 6.4 対象

場面の中心となった人物、チーム、集団などを表す自由入力項目である。

例：

- 選手名
- 監督名
- チーム名
- 主審
- ホームサポーター
- アウェーサポーター

## 7. 機能要件

### 7.1 共通機能

すべての画面で次の要素を提供する。

- アプリ名
- ホームへの導線
- 試合一覧への導線
- 場面一覧への導線
- 公開デモに関する案内
- PC とスマートフォンに対応した基本レイアウト

画面遷移には Next.js のルーティング機能を使用する。

### 7.2 ホーム画面

ホーム画面では、アプリの概要と登録状況を表示する。

#### 表示項目

- アプリ名
- アプリの説明
- 対象リーグ
- 対象シーズン
- 登録済み試合数
- 登録済み場面数
- お気に入り場面数
- 最近登録された場面 5 件
- 試合一覧への導線
- 場面一覧への導線
- 試合登録への導線
- 場面登録への導線

登録済み場面が存在しない場合は、試合登録と場面登録を案内する空状態を表示する。

### 7.3 試合一覧

登録済みの試合を一覧表示する。

#### 表示項目

- ホームチーム
- アウェーチーム
- スコア
- 試合日
- 登録されている場面数
- 試合詳細への導線

#### チーム絞り込み

固定 20 チームから 1 チームを選択し、選択したチームがホームまたはアウェーに含まれる試合を表示する。  
ホーム用とアウェー用の選択欄は分けない。

#### 並び替え

次の並び替えを提供する。

- 試合日の新しい順
- 試合日の古い順
- 登録日時の新しい順
- 登録日時の古い順

初期表示は試合日の新しい順とする。試合日が未入力の試合は、試合日順では末尾に表示する。

#### ページネーション

- 1 ページ 10 件
- 前ページへの移動
- 次ページへの移動
- ページ番号による移動
- 絞り込み・並び替え条件の維持
- 条件変更時は 1 ページ目へ戻す

一覧条件は URL 検索パラメーターで管理する。

#### 空状態

- 試合が 1 件もない場合
- 絞り込み条件に一致する試合がない場合

上記を区別して表示する。

### 7.4 試合登録

新しい試合を登録する。

#### 入力項目

| 項目               | 必須 | 入力方法               |
| ------------------ | ---: | ---------------------- |
| ホームチーム       | 必須 | 固定 20 チームから選択 |
| アウェーチーム     | 必須 | 固定 20 チームから選択 |
| 試合日             | 任意 | 日付入力               |
| ホームチーム得点   | 任意 | 数値入力               |
| アウェーチーム得点 | 任意 | 数値入力               |

#### 登録条件

- ホームとアウェーに同じチームを指定不可
- 固定 20 チーム以外を指定不可
- 試合日を入力する場合は対象シーズン内の日付のみ許可
- スコアは両方入力または両方未入力
- 得点は 0 以上の整数
- 試合登録数が上限未満であること

登録成功後は、登録した試合の詳細画面へ移動する。

### 7.5 試合詳細

選択した試合の情報と、その試合に登録された場面を表示する。

#### 表示項目

- 対戦カード
- スコア
- 試合日
- 登録日時
- 更新日時
- 登録されている場面数
- 関連する場面一覧
- 場面登録への導線
- 試合編集への導線
- 試合削除操作
- 試合一覧へ戻る導線

関連する場面が存在しない場合は空状態を表示する。

### 7.6 試合編集

試合登録と同じ項目を編集可能とする。  
更新成功後は試合詳細画面へ移動する。試合情報の変更は、その試合に関連する場面の表示にも反映する。

### 7.7 試合削除

関連する場面が存在しない試合のみ削除可能とする。

- 関連する場面が 0 件：削除可能
- 関連する場面が 1 件以上：削除不可

削除前に確認を表示する。削除成功後は試合一覧画面へ移動する。

### 7.8 場面一覧

登録済みの場面を一覧表示する。

#### 表示項目

- タイトル
- 場面の種類
- 発生時間
- 対象
- 対戦カード
- 試合日
- お気に入り状態
- 場面詳細への導線

「何が起きたか」と「なぜ印象に残ったか」の全文は一覧に表示しない。

#### キーワード検索

次の項目を部分一致検索の対象とする。

- タイトル
- 対象
- 何が起きたか
- なぜ印象に残ったか

チーム名はキーワード検索の対象に含めない。

#### チーム絞り込み

固定 20 チームから 1 チームを選択し、選択したチームが参加した試合に関連する場面を表示する。  
ホームとアウェーは区別しない。

#### 場面の種類による絞り込み

固定された場面の種類から 1 つを選択し、該当する場面を表示する。

#### お気に入り絞り込み

「お気に入りのみ」を選択した場合、`is_favorite` が有効な場面だけを表示する。

#### 並び替え

次の並び替えを提供する。

- 試合日の新しい順
- 試合日の古い順
- 登録日時の新しい順
- 登録日時の古い順

初期表示は試合日の新しい順とする。試合日が未入力の試合に関連する場面は、試合日順では末尾に表示する。

#### ページネーション

- 1 ページ 10 件
- 前ページへの移動
- 次ページへの移動
- ページ番号による移動
- すべての検索・絞り込み・並び替え条件の維持
- 条件変更時は 1 ページ目へ戻す

一覧条件は URL 検索パラメーターで管理する。

#### 条件リセット

検索・絞り込み・並び替え条件を初期状態へ戻す操作を提供する。

### 7.9 場面登録

登録済みの試合に対して新しい場面を登録する。

#### 入力項目

| 項目               | 必須 | 入力方法                       |
| ------------------ | ---: | ------------------------------ |
| 関連する試合       | 必須 | 登録済み試合から選択           |
| タイトル           | 必須 | 文字入力                       |
| 場面の種類         | 必須 | 固定選択                       |
| 発生時間           | 任意 | 文字入力                       |
| 対象               | 任意 | 文字入力                       |
| 何が起きたか       | 任意 | 複数行入力                     |
| なぜ印象に残ったか | 任意 | 複数行入力                     |
| お気に入り状態     | 必須 | チェックボックス、初期値は OFF |

#### 関連試合の指定

次の 2 つの導線を提供する。

- 場面登録画面で登録済み試合を選択
- 試合詳細画面から対象試合を選択済みの状態で場面登録画面へ移動

試合と場面を同じフォームで同時登録する機能は設けない。

#### 登録条件

- 関連する試合が存在すること
- タイトルが入力されていること
- 固定された場面の種類が指定されていること
- 各項目が文字数上限以内であること
- 場面登録数が上限未満であること

「何が起きたか」と「なぜ印象に残ったか」は両方未入力でも登録可能とする。  
登録成功後は、登録した場面の詳細画面へ移動する。

### 7.10 場面詳細

選択した場面のすべての情報を表示する。

#### 表示項目

- タイトル
- 場面の種類
- 発生時間
- 対象
- 何が起きたか
- なぜ印象に残ったか
- お気に入り状態
- 関連する試合情報
- 登録日時
- 更新日時
- お気に入り切り替え
- 場面編集への導線
- 場面削除操作
- 試合詳細への導線
- 場面一覧へ戻る導線

任意項目が未入力の場合は、該当する見出しと内容を表示しない。

### 7.11 場面編集

場面登録と同じ項目を編集可能とする。関連する試合も変更可能とする。  
更新成功後は場面詳細画面へ移動する。

### 7.12 場面削除

場面を単独で削除可能とする。

- 削除前に確認を表示
- 削除成功後は場面一覧へ移動
- 関連する試合は削除しない
- 試合に関連する場面数へ削除結果を反映

### 7.13 お気に入り切り替え

場面のお気に入り状態を切り替える。

#### 操作可能な画面

- 場面一覧
- 場面詳細

お気に入り変更のために場面編集画面へ移動する必要はない。送信中は操作を無効化し、二重送信を防止する。  
楽観的更新は必須としない。

### 7.14 登録件数上限

次の登録件数上限を設ける。

| データ |   上限 |
| ------ | -----: |
| 試合   |  50 件 |
| 場面   | 100 件 |

上限到達時の挙動は次のとおりとする。

- 新規登録を拒否
- 既存データの編集は可能
- 既存データの削除は可能
- 古いデータの自動削除は行わない
- データ削除後、上限未満になれば再び登録可能

件数上限はサーバー側で確認する。

### 7.15 入力エラー

入力エラーはフォーム内に表示し、入力済みの値を可能な範囲で保持する。  
主な対象は次のとおりである。

- 必須項目の未入力
- 不正な選択値
- 文字数上限超過
- 不正な数値
- 不正な日付
- 同じチーム同士の試合
- スコアの片方だけの入力
- 存在しない関連試合
- 登録件数上限
- 関連する場面がある試合の削除

### 7.16 ローディング・エラー・404

#### ローディング

主要な一覧・詳細画面にローディング表示を用意する。

#### 予期しないエラー

DB 接続失敗や想定外の処理失敗は、共通エラー画面で扱う。SQL、接続情報、内部エラーの詳細は利用者へ表示しない。

#### 404

次の場合は 404 画面を表示する。

- 存在しない試合 ID
- 存在しない場面 ID
- 削除済みデータへのアクセス
- ID として解釈できない値

### 7.17 Metadata

次の Metadata を設定する。

- アプリ共通の Metadata
- 各固定ページのタイトル
- 試合詳細の動的タイトル
- 場面詳細の動的タイトル

例：

```text
場面一覧 | Football Moment Archive
Arsenal vs Liverpool | Football Moment Archive
終了間際の決定的なセーブ | Football Moment Archive
```

## 8. 非機能要件

### 8.1 UI・レスポンシブ対応

- PC とスマートフォンの両方で基本操作が可能
- 一覧、詳細、フォームの表示が画面幅に応じて調整される
- 不要な横スクロールを発生させない
- 長いタイトルや文章を適切に折り返す
- スマートフォンでも主要なボタンを操作しやすい大きさにする

端末ごとに異なる専用機能は設けない。

### 8.2 アクセシビリティ

最低限、次の内容に対応する。

- 適切な見出し構造
- フォーム項目と `label` の関連付け
- 必須・任意の文字表示
- エラーを色だけで表現しない
- キーボードによる主要操作
- 視認可能なフォーカス表示
- お気に入り状態を文字または支援技術へ伝達
- 削除操作を通常のリンクと区別

### 8.3 セキュリティ

認証や Rate Limiting は設けないが、基本的な安全対策は実施する。

- Server Action で入力値を再検証
- SQL のパラメーター化
- DB 接続情報を環境変数で管理
- DB 接続情報をブラウザへ公開しない
- サーバー専用コードを Client Component から参照させない
- 内部エラーの詳細を画面へ表示しない

### 8.4 性能・規模

最大データ件数は試合 50 件、場面 100 件とする。小規模データを前提とし、全文検索エンジンや複雑なキャッシュは導入しない。  
一覧取得では DB 側で検索条件、並び替え、`LIMIT`、`OFFSET` を適用する。

### 8.5 対応環境

- 最新の主要 Chromium 系ブラウザで基本動作を確認
- PC ブラウザで確認
- スマートフォン実機で確認

複数ブラウザを対象とした厳密な互換性保証は行わない。

### 8.6 データ復旧

シード SQL により、開発用または公開用の初期データを再投入できる状態を維持する。  
自動バックアップや管理画面による復旧機能は実装しない。

## 10. 完成条件

次の一連の操作が正常に行えることを MVP の完成条件とする。

1. 固定 20 チームから試合を登録できる
2. 登録した試合の詳細を確認できる
3. 試合に場面を追加できる
4. 登録した場面の詳細を確認できる
5. 場面のお気に入りを切り替えられる
6. 場面一覧でキーワード検索と絞り込みを行える
7. 試合一覧と場面一覧を並び替えられる
8. 試合一覧と場面一覧でページ移動できる
9. 試合と場面を編集できる
10. 場面を削除できる
11. 関連する場面がない試合を削除できる
12. 関連する場面がある試合の削除を拒否できる
13. 入力エラーをフォーム上で確認できる
14. 存在しないデータで 404 画面を表示できる
15. 予期しないエラーで共通エラー画面を表示できる
16. PC とスマートフォンで基本操作ができる
17. シード SQL により初期データを再投入できる
18. Vercel 上の公開環境で主要機能を利用できる
